# AI usage log

A running log that becomes the README's "How I used AI" section. Add 1–3 lines per phase.

**Tools:** Claude Code (Claude Opus) in VS Code.

**How I worked:** I researched the domain and wrote the plan first, then asked for one phase at a time. Business rules were written as pure functions with tests, so AI output could be checked mechanically. I reviewed every diff before committing.

| Phase | What AI did | What I changed / caught |
|---|---|---|
| Planning | Researched PEN Group's context (franchised UK higher education, multi-campus, Student Finance-funded students) and turned the brief into a prioritised feature list, phased plan and decisions log. | Cut scope to the four workflows; chose the edge cases worth building. |
| 0 — Scaffold | Scaffolded Next.js 16 + Tailwind 4 + shadcn/ui, Prisma 7 (driver adapter `@prisma/adapter-pg`, `prisma.config.ts`), Docker Postgres, Vitest, npm scripts. | npm's `latest` tag for Prisma was an **8.0 release candidate**, so I pinned stable 7.10.0. Scaffold's `.gitignore` (`.env*`) would have hidden `.env.example`, so I added an exception. `prisma init` dropped AI-agent skill files for three editors into the repo, so I removed them. Vitest 5 needed `@types/node` 22 to match the Node 22 runtime. |
| 0 — No-Docker path | I pushed back on Docker being required. AI tested Prisma's embedded Postgres (`prisma dev`) against our real client: parallel queries, transactions and `migrate dev` all worked, so it became a documented zero-install option alongside Docker and "bring your own Postgres". | Prisma 7 refuses `migrate reset` when run by an AI agent without the user's explicit consent. AI didn't bypass the guard; it deleted its own throwaway test server instead. |
| Design — tokens | Claude Design produced the theme tokens from a structured brief ([DESIGN_BRIEF.md](DESIGN_BRIEF.md), [DESIGN_PROMPTS.md](DESIGN_PROMPTS.md)): teal primary, neutral zinc base, semantic status tokens (overdue / late / withheld / info / warning / success) with AA foreground pairs, light + dark. | Dropping its `globals.css` in as-is would have broken the installed shadcn "Nova" components: it removed `shadcn/tailwind.css` (the `data-open`/`data-closed` variants that dialogs and dropdowns animate with), `--font-heading`, and the `rounded-xl`/`rounded-4xl` radius steps. I merged instead: design colours and base styles, Nova plumbing kept. Original kept unmodified in `design/registry-globals.css`. |
| Design — import | Claude Design produced 32 screens (staff 1440px, student 1440px + 390px) from six staged prompts. Claude Code read the canvas directly from its link, saved every screen's source to `design/canvas/`, and wrote [UI_GUIDE.md](UI_GUIDE.md): screen → route map, design hex → theme token table, one status-badge vocabulary, layout/density rules, and the behaviour each screen specifies. CLAUDE.md imports the guide so every later session builds to it. | The design surfaced better domain decisions than the plan had: modules shared across programmes, results released per assessment, a "student still sees 58 until you re-publish" snapshot, notes required on extensions and withholds. Adopted these and updated DECISIONS (D12, D13, D19–D23) and the seed plan. Rejected one thing: receipts saying "we've emailed you" (no email in this build, D24). Excluded `design/` from Tailwind's class scanning so mockup HTML doesn't bloat the CSS. |
| 1 — Schema, rules, seed | Wrote the Prisma schema (15 tables), pure business-rule modules (UK time incl. clock changes, academic years, student numbers, money, fee allocation, submissions/lateness, enrolment transitions, result release) with 70 Vitest tests, and a seed that reproduces the design's numbers using offsets from today. Verified `db:setup` on a fresh Docker database and on Prisma's embedded Postgres, and that the seed is repeatable. | Tests were written from the design's figures (e.g. Aisha £7,151.25 with £2,383.75 overdue 21 days; Tom 1d 3h late), so the maths is checked against the spec, not against itself. Caught and removed a stray unused import the AI added. Simplified the plan: status history folded into the audit log (D25); added the roster rule the plan had missed (D26). Hand-rolled the UK time zone helpers with tests for both 2026 clock changes rather than adding a date library. |
| 2–8 — App build | Built the service layer, 12 JSON API routes, staff screens (dashboard, students, profile with 5 tabs, fees, assessments, roster and marking, results) and student screens (assessments with upload, results, account, phone layout) from the design files, reading the bundled Next.js 16 docs first (async `params`/`cookies`, `RouteContext`, `proxy` rename). Drove a real browser (Playwright) to compare every screen with its design file and to run the workflows end to end; probed the API with curl for role checks and edge cases. | **Caught in testing, then fixed:** server components passed Lucide icon *functions* into client nav links (runtime error); en-GB `Intl` printed "Sept" where the design says "Sep" (own month table + test); lint flagged two dialogs resetting state in `useEffect` (now keyed inner forms); the server reported only the first form error (now all at once, D29); a renamed text file got a self-contradicting message (fixed + test). **Product gap found by using it:** the seed had Aisha's result already withheld, so the key "Consider withholding" alert never appeared; added an earlier withheld assessment so both states are visible. **Verified, not assumed:** a student's withheld mark, reason and note don't appear anywhere in their page's HTML (an apparent hit was a React reference id). Removed several bits of stray code the AI left in (unused re-exports, a pointless hidden element). |
| QA — end to end | On request, ran a full end-to-end pass with Playwright MCP: 137 checks across 13 areas in a real browser from a fresh seed, plus direct API probes ([TESTING.md](TESTING.md)). | Found and fixed 3 bugs the unit tests couldn't see: withdrawal cancelled a **prepaid** instalment (an automatic refund decision; now only unpaid ones), "Next due" ignored a second instalment on the same date, and the withheld-results queue linked to the wrong assessment. Also fixed 4 rough edges (required-field message, a date format, error reporting, a file message). Re-tested each fix in the browser. |
| Dev workflow | Tried an all-in-one `npm run dev` that started the database, migrated, seeded when empty and launched Next.js. It worked in all four cases tested, but I judged it too much hidden behaviour and asked for something simpler: start the database → `npm run dev` (migrations only) → `npm run db:seed` when wanted (D33). | Testing the empty-database path exposed a real bug: with no students, the student and staff layouts redirected to each other forever. The student view now explains there are no students, and every empty screen points to `npm run db:seed`. |
| Reviewer dry run | Tore down every local database and re-ran the README from a clean copy of the repo (only files git would ship): `npm install` → `npm run db:up` → `npm run dev` (empty app with hints) → `npm run db:seed`; also the no-Docker option, `npm test` and `npm run build`. | The dry run surfaced "12 high severity vulnerabilities" on install. Found `shadcn` (a code-generator CLI) listed as a runtime dependency and moved it to dev; pinned two vulnerable Prisma CLI sub-dependencies with `overrides` and re-verified Prisma end to end. Result: 0 in production dependencies; the remaining dev-tool advisory has no patched release and is documented in the README. |
